1. Development Approach and Architectural Decisions
I utilized Claude to develop a comprehensive instruction plan for this project, ensuring a thorough understanding of all requirements, constraints, and conditions that needed to be addressed. Subsequently, I consulted ChatGPT to explore various architectural choices and design decisions. For instance, I requested a comparative analysis of PostgreSQL and MongoDB as the primary database to determine the most suitable option for this project.
The AI model proposed using a Minimum Spanning Tree (MST) algorithm to address the missing topology, which would then be attached to a Distribution Transformer (DT). The topology for the Low Tension (LT) network would be generated by traversing the tree using Breadth-First Search (BFS).
However, I identified a limitation in this approach: considering every pole as a potential connected node for MST calculation would result in numerous implausible connections. I suggested that only poles within a specified distance threshold should be considered as potential connections to reduce computational complexity and improve accuracy. The AI model acknowledged this constraint and refined the solution to first filter nodes based on proximity before applying the MST algorithm. This iterative refinement produced a more practical and efficient solution.


2. Incident Grouping and Duplicate Detection
Initially, the AI model suggested excluding time as a factor when grouping incidents. I challenged this approach by raising a scenario: if telemetry data is received from the same subtree within a short time interval, wouldn't this result in multiple tickets being created for what is essentially the same incident? In response, the AI model revised its recommendation to incorporate time as a factor in incident definition, alongside spatial boundaries. This enhancement enables the system to continuously update the boundary and confidence level of an existing incident rather than creating duplicate entries for the same outage event.
